## How to get to it (user POV)

### 9. Manage owner sign-in, desktop pairing, and vault recovery

**Who starts:** The owner. **Where:** Console route `/settings`; the Add data screen links here as `Developer mode` when connectors are hidden. There is no sidebar or palette entry. The page shows owner-password when a password source exists, and session/pairing sections when owner sessions are enabled. `Desktop` and `Vault recovery code` appear only in the managed desktop host. **Form:** Self-hosted server console; the DataConnect desktop app receives a pairing code; recovery export is managed-desktop-only. **Terminal/account:** No outside account. Deployment config may be needed to configure pairing origin/identity or an environment-sourced password. **Code:** `apps/console/src/app/(console)/settings/page.tsx:24-109`; Add data link `apps/console/src/app/(console)/components/source-setup-catalog.tsx:675-682`; settings components below (V).

1. The page is headed “Settings” with description “Control optional features for this browser and the way this Personal Server can be reached.” `Owner password` appears when the server reports a password source. `Owner sessions` and `Attach a desktop app` appear when owner sessions are enabled. `Desktop` and `Vault recovery code` appear only when `PDPP_MANAGED_DESKTOP_HOST=1`. **V** `apps/console/src/app/(console)/settings/page.tsx:24-109`.
2. Under `Attach a desktop app`, the description says “Pair the DataConnect desktop app with this server. The desktop shows this server's console and signs in as you.” Click `Create pairing code` (while working: “Creating…”). The page shows server address, pairing code, server ID, and pairing link, with `Copy` buttons. Instructions: “In the DataConnect desktop app choose Connect to a server, then paste the link (or the address and the code).” The desktop should show the same server ID. The console calls `POST /owner/desktop-pairings`; the server issues the one-use code and pairing link. This route mounts only if the server has a canonical public origin and an instance identity configured. **V** `apps/console/src/app/(console)/settings/page.tsx:86-93`; `apps/console/src/app/(console)/settings/desktop-pairing-setting.tsx:50-129,201-223`; `apps/console/src/app/(console)/settings/desktop-pairing-actions.ts:24-54`; `reference-implementation/server/owner-auth.ts:199-210,1692-1701`.
3. The code works once and expires in 10 minutes. The timer says “Expires in M:SS”; at expiry the page removes the code and link and says “Expired. Create a new code.” A paired computer appears in `Owner sessions` and can be signed out there. There is no separate revoke control for an unused pairing code; create another after expiry. **V** `apps/console/src/app/(console)/settings/desktop-pairing-setting.tsx:19-21,37-62,133-160,220-223`; `apps/console/src/app/(console)/settings/desktop-pairing.ts:120-137`.
4. In `Owner sessions`, `Devices and browsers` lists device label, optional `Current session`, `Started <time> · Last seen <time>`, and `IP address: <address>` (or “Unavailable”). Each row has `Sign out`; when other sessions exist the page offers `Sign out other devices`, and when any sessions exist it offers `Sign out all devices`. Copy says: “These devices and command-line tools can access this Personal Server. Signing one out takes effect immediately.” The separate `Command-line access` list says “No owner tokens are active.” when empty; otherwise it lists each label, creation time and expiry/“Never”, with `Revoke token`. The console reads `GET /owner/sessions`; individual and bulk controls call the matching revoke endpoints. **V** `apps/console/src/app/(console)/settings/owner-sessions-setting.tsx:50-134`; `apps/console/src/app/(console)/settings/owner-sessions-actions.ts:1`; `reference-implementation/server/owner-auth.ts:1612-1671`.
5. `Owner password` is not an API token. On desktop, DataConnect stores it on the computer for signing in on other devices. When local reveal proof is available, `Reveal password` displays it; the page warns “Make sure no one else can see your screen before revealing the password.” Buttons are `Copy to clipboard` / `Reveal again`; use it on another device’s `/owner/login` page. `Set password` or `Change password` opens a native window; success says “Password window opened.” On a managed desktop with an environment password, the person is told to change `DATACONNECT_OWNER_PASSWORD` or `PDPP_OWNER_PASSWORD` and restart. On a self-hosted environment-backed server, `Change password` is disabled and the person is told to change `PDPP_OWNER_PASSWORD` and restart. The normal form asks for current password, new password, and confirmation, requires at least 15 characters, and says “Your current browser stays signed in; other sessions are ended.” **V** `apps/console/src/app/(console)/settings/owner-credential-setting.tsx:65-114`; `apps/console/src/app/(console)/settings/owner-password-setting.tsx:41-76,107-160,165-220`; `apps/console/src/app/(console)/settings/owner-credential-actions.ts:1`; `reference-implementation/server/routes/owner-credential-reveal.ts:99`; `reference-implementation/server/owner-auth.ts:1492-1502`.
6. On managed desktop only, `Vault recovery code` describes a printable code for restoring access if the system keychain loses its key. The person sees: “This code restores encryption keys only. Keep your database backup separately. Anyone who has both can read everything in your Personal Server vault.” Click `Export recovery kit` (while working: “Exporting…”); the code is shown on the page with `Copy kit`, and the action changes to `Export kit again`. If clipboard copy fails: “Could not copy automatically. Select the kit above and copy it manually.” The kit contains encryption keys, not the database file. **V** `apps/console/src/app/(console)/settings/page.tsx:94-109`; `apps/console/src/app/(console)/settings/recovery-key-setting.tsx:9-104`; server exporter `reference-implementation/server/routes/owner-recovery-kit.ts:38-71`.

**Branches/failures:** Pair creation can show “Could not create a pairing code.” or “The server sent an unexpected pairing response.” If pairing routes were not mounted because public origin or instance identity is missing, the console still shows `Create pairing code`, but the request fails. If the desktop submits an invalid or expired code, the server returns “This pairing code is not valid. Create a new one in the server's settings.” If it cannot start a session, it returns “Could not start a session. Create a new pairing code.” Owner-session actions display the server message or “Could not update owner access.” Password change rejects a short password with “Use at least 15 characters for the new password.” or a mismatch with “The new passwords do not match.” Recovery export fails with “Credential encryption key is not configured; no server recovery kit can be exported.” **V** `apps/console/src/app/(console)/settings/desktop-pairing-actions.ts:24-54`; `reference-implementation/server/owner-auth.ts:1038-1049,1143-1188,1692-1701`; `apps/console/src/app/(console)/settings/owner-sessions-setting.tsx:33-44`; `apps/console/src/app/(console)/settings/owner-password-setting.tsx:41-51`; `reference-implementation/server/routes/owner-recovery-kit.ts:38-71`.

**Afterwards:** The paired desktop appears under `Owner sessions`; the owner can sign out one device, other devices, or all devices, and revoke command-line tokens. Password changes end other sessions/tokens. The recovery kit is not revoked or listed; it can be exported again. **V** cited code.

**Rough edges:** `/settings` is not in the main navigation and has no Jump command; a contextual `Developer mode` link appears only when connector cards are hidden. The page shows the pairing control when owner sessions are enabled, but the server mounts pairing routes only when public origin and instance identity are configured. Pairing code expires quickly and then disappears, with only “Create a new code” as recovery. Owner password changes differ by server configuration and may require editing an environment variable and restarting the server. A recovery kit is a secret key backup, not a data backup; the database must be retained separately. The label “Owner tokens” is used for API bearers, while browser/device sessions are a separate list. **V** cited code.
