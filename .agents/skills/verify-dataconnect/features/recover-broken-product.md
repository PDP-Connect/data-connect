## How to get to it (user POV)

### 10. Product broken: startup, database, port, network, disk

**Who starts it:** product on startup or owner after a failure. **Where:** tray, console, OS logs, Docker logs, Deployment. **Forms:** both.

1. [V] Server fails to start: desktop logs `Unified DataConnect startup` failure and sets tray status Error; tray still offers “Show logs”. A missing encryption key with encrypted vault logs the specific key error and opens recovery window. [src-tauri/src/unified.rs:770-783]
2. [V] Docker startup warm-up: first request can receive a startup page that retries automatically; wait. If still unavailable after services report ready, run `docker logs --tail=200 pdpp`. [deploy/docker/README.md:93-97]
3. [I] Port taken: desktop server supervisor gets bind error in logs and tray Error; no dedicated port conflict page or page-level command is evidenced. For Docker `docker run`, port mapping conflict is Docker CLI output; deployment docs don’t provide a specialized UI. **I** for exact CLI error text because it is generated by OS/Docker.
4. [I] Database missing/unreadable: startup error appears in desktop log/tray status or deployment service logs; no separate database missing screen. Recovery key flow handles missing key, not missing DB. **I** from supervisor/error boundary; exact backend error varies.
5. [V] Network unavailable / remote access forwarding timed out: Remote access shows background service unreachable or check failure, “Changes are paused until remote access can be checked.” The page’s route handler timeout is 15s from request send; it shows details with “Copy diagnostics” and may retry/poll. [apps/console/src/app/(console)/settings/README.md:7; apps/console/src/app/(console)/settings/remote-access-setting.tsx:1018-1029; apps/console/src/app/(console)/settings/reachability-errors.ts:12-93]
6. [I] Disk full: if diagnostics can still run, `/deployment` → “Warnings” can show “Disk headroom is low” with a server message. Below 2 GiB it says a restart/build may fail with “No space left on device” and suggests Docker prune commands; 2–5 GiB suggests `docker system prune`. There is no standalone disk-full recovery page. If storage is already exhausted, startup or writes may fail into logs or a generic connection/run error. [reference-implementation/server/deployment-diagnostics.ts:727-744; reference-implementation/vendor/operator-ui/src/components/views/deployment-diagnostics-view.tsx:188-218]
7. [V] Desktop “Show logs” opens the OS log directory's `DataConnect.log` in the default viewer. Docker quickstart logs are `docker logs pdpp`; production logs are the Compose service logs. Fly uses `fly logs --app "$APP"`; Railway uses Core deploy logs. [src-tauri/src/unified.rs:801-805,2633-2645; src-tauri/src/commands/file_ops.rs:1306-1318; deploy/docker/README.md:65-97,191-212; deploy/flyio/README.md:70-76; deploy/railway/README.md:85-89]

**Rough edges:** product errors do not consistently distinguish missing DB, busy port, full disk, and no network in a user page; the actionable evidence is often an OS/provider log. Do not invent exact wording for failures produced by the OS, Docker, Fly, Railway, or database driver.

## Driving it with Playwright

**Journey status:** `partly`. **Journey file:** `product-health`. **Combined isolated run:** `product-health`: **pass**.

**What it verifies:** The capture reaches the checks an operator would inspect first.

**Reaches:** The `/deployment` readiness page renders.

**Stops at:** No broken server, database, port conflict, disk floor, or remote-access outage is intentionally induced.

**Run one journey:**

```sh
TEST_SANDBOX_REQUIRE=1 scripts/test-sandbox/test-sandbox --net none --pidns --scratch "$VERIFY_DIR/sandbox-scratch" -- node e2e/harness.mjs capture.spec.ts --output "$VERIFY_DIR/playwright-output" --grep "journey: product-health"
```

**Evidence:** `evidence/product-health/<run-id>/` contains desktop and phone screenshots plus visible text.

## Gotchas

A healthy page cannot verify recovery behavior. Host-level faults require a separate controlled test.
