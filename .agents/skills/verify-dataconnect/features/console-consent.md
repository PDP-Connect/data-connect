## How to get to it (user POV)

### 6. Approve a hosted MCP request in the console

**Who starts:** ChatGPT, Claude.ai, Claude Code, Codex, or another OAuth MCP client. **Where:** Console `/consent?challenge=<opaque id>`, redirected from `GET /oauth/authorize` when the client did not send `authorization_details` or `connector_id`. This page has no console sidebar/topbar; it is a standalone consent experience. The server stores and validates the protocol challenge; the console fetches a render model and posts the decision back. **Code:** `reference-implementation/server/routes/as-authorize.ts:1534-1610,1732-1801`; `apps/console/src/app/consent/page.tsx:4-89`; `apps/console/src/app/consent/actions.ts:1-116`; `apps/console/src/components/consent-screen/consent-screen-client.tsx:252-478,482-850`; model `apps/console/src/components/consent-screen/consent-screen-model.ts:22-145` (V).

1. The user lands on `/consent?challenge=…`. It verifies owner session before reading the request and preserves the challenge across login. Missing, unknown, expired, or consumed challenge becomes not-found. This is a console route and client component, despite being launched by the authorization server. **V** `apps/console/src/app/consent/page.tsx:38-89`.
2. Header identifies the app, trust state/domain, and links the client published. The screen says “Terms” and shows server-provided purpose and retention text. The source section is headed “What it can read” with an `N sources` count. Empty source state says: “You have no connected sources yet, so there is nothing to share. Connect a source first, then start this request again.” **V** `apps/console/src/components/consent-screen/consent-screen-client.tsx:695-734`; model/client header functions earlier in same file.
3. Optional “Search sources” filters the app’s available sources by source name, account label, and stream labels/names. No match says: “No sources match ‘<query>’. Clear the search to see everything.” A source row has checkbox “Share data from <source>”; each data type/stream has “Share <stream> from <source>”. Streams preselected by the server appear selected; a source opens initially if any stream is selected. No source-level default selection is added by the client. **V** `apps/console/src/components/consent-screen/consent-screen-client.tsx:372-478,497-530,735-769`.
4. For a selected stream, `Change` expands “Choose fields to share” with `Select all` and `Select none`; required fields are checked and disabled, labeled `Required`. If fields are unavailable, copy says “This grant covers all N fields in <type>.” Date inputs appear only when the stream declares a time field. They have `from`, `to`, and `Apply to all selected streams`; otherwise it says “No date range for this data type.” Time bounds narrow which records may be read; separate from the expiry below. **V** `apps/console/src/components/consent-screen/consent-screen-client.tsx:280-369`; `apps/console/src/components/consent-screen/consent-screen-model.ts:33-56,137-145`.
5. The side panel says “What you’re allowing” (accessible name), summarizes `<N> sources · <N> of <N> streams selected`, and says “You’ll return to <host>” when known. `Access duration` has a date input labeled “Access ends”, preset chips `90 days` and `1 year`, and a `No end date` checkbox; when checked, it says “Access never expires.” The default is `90 days` (the date input starts at today plus 90 days). The authorization’s access mode is fixed by the server to `continuous` on this page; there is no `One-time access` control here. The server-rendered compatibility helper defaults to `Ongoing access` and offers `One-time access`, with exact copy “<app> can read the data you select, including new matching records, until you revoke access.” / “<app> can start one retrieval. It can’t start another without your approval.” Its expiry field is “When this access ends”, hint “You can revoke it sooner at any time.”, and options `90 days`, `1 year`, `No end date` (default `90 days`; hidden for one-time access). This helper is only used to re-render compatibility validation errors; current `/oauth/authorize` does not show it on its normal path. **V** console `apps/console/src/components/consent-screen/consent-screen-client.tsx:497-510,799-819,856-925`; model `apps/console/src/components/consent-screen/consent-screen-model.ts:104-107`; server `reference-implementation/server/routes/as-consent-ui-helpers.ts:2614-2626,3180-3199,3714-3725`; `reference-implementation/server/hosted-mcp-grant-expiry.ts:29-54`.
6. Click `Allow access` (disabled until at least one stream is selected) or `Cancel`. Empty choice says “Choose at least one data type to allow access.” While submitting, button says “Working…”. Success navigates out to the client’s redirect URL and replaces browser history so Back does not re-open the consumed challenge. Errors are shown inline; generic fallback: “Something went wrong. Nothing was shared.” A server error description is preferred; missing redirect yields “The server approved this request but did not say where to return. Nothing was shared.” **V** client `apps/console/src/components/consent-screen/consent-screen-client.tsx:825-846,676-689`; actions `apps/console/src/app/consent/actions.ts:46-71`.

**Branches/failures:** A malformed custom expiry date can show “That is not a date this server can use. Pick another.” A past date shows “Choose an end date in the future.” A date beyond five years shows “Choose an end date within five years, or choose no end date.” Empty/unknown/expired challenge is not-found before the form. Missing or mismatched decision review shows the server’s description or the generic “Something went wrong. Nothing was shared.” **V** `reference-implementation/server/hosted-mcp-grant-expiry.ts:84-102`; `reference-implementation/server/routes/as-authorize.ts:1513,1732-1801`; console client/actions cited above.

**Defaults and outcomes:** Per-stream and field selections follow the server’s model; the data date range starts empty (“All dates”). Required fields cannot be unchecked. Access duration defaults to `90 days`; the server includes `1 year` and `No end date` options, and permits a custom future date through five years. Access mode is fixed to ongoing (`continuous`); the owner cannot choose one-time access on this current console page. Approve creates the grant/package only after the server validates the review digest and selected source/stream/field/range values. Cancel calls reject and returns the server’s redirect. **V** `apps/console/src/components/consent-screen/consent-screen-client.tsx:497-510,614-685,856-925`; `reference-implementation/server/routes/as-consent-ui-helpers.ts:888-890`; `apps/console/src/app/consent/actions.ts:74-116`; server `reference-implementation/server/routes/as-authorize.ts:1732-1801`.

**Rough edges:** This `/consent?challenge=…` page is rendered by the console, not server HTML. The `/consent?request_uri=…` page is server-rendered and has different copy and controls. A server-rendered hosted-MCP source-picker helper remains for compatibility validation responses but current `/oauth/authorize` sends no-source requests here instead. The server has a one-time access mode but the current console page fixes access mode to ongoing and exposes no one-time choice. The page’s backend request/challenge errors can become generic Next not-found or thrown errors; it does not show a friendly expired-request panel. Expiry values are supplied by the server, even though this commit currently supplies 90 days, one year, and no end date. **V** cited files.

## Gotchas

The console page requires a real pending challenge and an owner session. The baseline 404 is not a consent-flow pass.
