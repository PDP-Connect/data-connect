# DataConnect feature map

One file records each mapped user flow. The capture stack uses a fresh disposable reference server and a production console.

## Status meanings

- `yes`: the journey covers the mapped flow end to end.
- `partly`: a journey reaches one or more real screens or actions, then stops before the full mapped flow.
- `no`: no feature journey is declared.
- `pass` and `fail` are Playwright outcomes. They describe the declared journey, not the whole product flow.

## Conventions

- Each feature file retains mapped steps, visible copy, product forms, branches, and repo-relative source references.
- Journey JSON lives in `e2e/journeys/`. A journey is an isolated Playwright test; an index result records the latest combined run.
- Evidence uses paths relative to the operator-selected `$VERIFY_DIR`; each captured view has a desktop PNG, phone PNG, and visible text.
- The all-journey command runs every declared journey and the route baseline in one harness build. The skill file gives the command.
- A failed assertion remains failed. A baseline screenshot or route 404 does not count as a passed product flow.
